# 給 Gemini Canvas 的生成規格（資訊大富翁）

這份是**貼給 Canvas 的提示詞 + 契約**。
目的：讓 Canvas 發揮視覺長處，但產出的東西能直接接進 repo，
不會重演 unit 13/14/15/19/20/21「畫面漂亮但沒存分數、徽章不會亮」的情況。

用法：把下面「提示詞」整段複製貼進 Gemini Canvas。
拿回成品後照最下方「驗收清單」逐條檢查，再交給我整合。

---

## 提示詞（整段複製）

```
請做一個給台灣國小一到三年級學生的「資訊大富翁」網頁遊戲，單一 HTML 檔。

【畫面風格 — 這是重點】
- 這是一張「地圖」，不是一排方塊。要有場景感。
- 森林主題：畫出地面、草叢、樹木、遠山、天空，有遠近層次。
- 路徑要蜿蜒（S 形或曲線），不要等距直線排列。
- 格子是路上的「石板 / 木樁 / 蘑菇」，彼此造型有變化，不要六個一模一樣。
- 棋子是一隻有個性的小動物角色，會眨眼、會呼吸、跳躍時有表情，
  不要只是把 emoji 放進白色圓圈。
- 色彩要有層次：同一個綠色系也要分出亮部暗部，加上暖色點綴。
- 走過的格子與未走的格子，視覺上要一眼分得出來。

【玩法】
- 6 個格子：起點 → 4 個問答格 → 1 個 BOSS 格。
- 按「擲骰子」前進 1-3 格，踩到問答格跳出題目卡，三選一。
- 答對得 10 金幣，BOSS 得 50 金幣。
- 答錯不扣分，可以無限重試（低年級不要有挫折感）。
- 抵達終點依金幣數給 1-3 顆星。

【動畫要飽滿】
骰子翻滾、棋子跳躍要有擠壓拉伸、答對要有粒子與金幣飛行、
數字要滾動不要直接跳、BOSS 過關要有彩帶與畫面震動。

=============== 以下是技術約束，請務必遵守 ===============

1. 單一 HTML 檔，所有 CSS / JS 內嵌，不要用任何建置工具或框架。
2. 不要引用任何外部圖片、音效、影片檔。
   插畫請用 inline SVG 或 CSS 繪製；音效請用 Web Audio API 即時合成。
   （唯一允許的外部資源是 Google Fonts 的 Noto Sans TC）
3. emoji 只能使用 2015 年以前就存在的：
   ✅ 🌲 🌱 ❓ 👑 ⭐ 💰 🐰 🎉 🔊
   ❌ 🪙 🪴 🫠 這類 2020 年後的新 emoji
   理由：教室電腦是舊版 Windows，新 emoji 會顯示成空白方塊。
4. 進度存 localStorage，key 一律用這個前綴，不要自己另外取名：
       edtech-board-progress   （JSON：{ pos, coins, done: [] }）
       edtech-board-best       （數字：歷史最高金幣）
5. 必須支援 `@media (prefers-reduced-motion: reduce)`：
   該模式下關閉所有動畫，但遊戲仍要能玩。
6. 手機（寬 390px）要能看到「整張地圖」，不可以橫向捲動。
   窄螢幕請改成蛇形折行或縮放整張地圖。
7. 字級：題目文字至少 20px，選項至少 18px（一到三年級 + 教室投影）。
   題目用字請控制在低年級識字量：盡量用常用字，長句拆短句，
   必要時用圖示或 emoji 輔助理解。
8. 所有可點擊元素要有 cursor: pointer 與明顯的 hover / 按下回饋。
9. 題目資料請集中成一個 JS 陣列常數 QUESTIONS，
   格式固定為 { q: '題目', opts: ['選項1','選項2','選項3'], a: 正解索引 }，
   方便老師之後自己加題目。
10. 請在程式碼裡加中文註解說明各區塊用途。
```

## 驗收清單（拿回成品後逐條檢查）

視覺（Canvas 的強項，主要看這幾點有沒有做到）
- [ ] 有場景層次（天空／遠山／地面／前景），不是純色背景
- [ ] 路徑蜿蜒，格子造型有變化
- [ ] 棋子是有表情的角色，不是 emoji 放圓圈
- [ ] 走過 / 未走過的格子一眼可分

契約（Canvas 最常漏的，一定要查）
- [ ] 真的是單一 HTML，沒有 import 外部 js/css
- [ ] 沒有引用任何外部圖片或音效檔（搜尋 `src=` 與 `url(` 確認）
- [ ] localStorage key 是 `edtech-board-*`，不是它自己取的名字
- [ ] 沒有用到 2020 後的新 emoji（搜尋 🪙 🪴 🫠 等）
- [ ] 有 `prefers-reduced-motion` 區塊
- [ ] 390px 寬不會橫向捲動
- [ ] `QUESTIONS` 是獨立常數陣列，格式正確

## 分工建議

| 誰 | 做什麼 |
|---|---|
| Gemini Canvas | 場景插畫、角色、路徑造型、動畫表現 |
| 蛋糕 | 出題目內容、決定難度與教學目標 |
| Claude | 契約制定、驗收、整合進 repo、修相容性問題、接首頁入口、寫 SDD |

**為什麼要這樣分**：Canvas 一次性生成的視覺強，但不會遵守專案慣例，
也不會考慮教室舊機器、螢幕閱讀器、減少動態這些邊界情況——
那是整合階段要補的。先立契約能讓補的量大幅下降。
