# 給 Gemini Canvas 的生成規格（資訊大富翁）

這份是**貼給 Canvas 的提示詞 + 契約**。
目的：讓 Canvas 發揮視覺長處，但產出的東西能直接接進 repo，
不會重演 unit 13/14/15/19/20/21「畫面漂亮但沒存分數、徽章不會亮」的情況。

用法：把下面「提示詞」整段複製貼進 Gemini Canvas。
拿回成品後照最下方「驗收清單」逐條檢查，再交給我整合。

---

## 提示詞（整段複製）

```
請做一個給台灣國小一到三年級學生的「資訊大富翁」網頁遊戲，單一 HTML 檔。

【主要使用情境 — 先讀這段再設計版面】
最主要的用法是**老師在教室用單槍投影，全班一起玩**，所以
**橫向寬螢幕是主版面**，請以它為設計基準（約 1280×800）。
手機直立是次要情境，用 CSS media query 另外調整即可，
**不要把整體設計改成直立式**。

【畫面風格 — 這是重點】
- 這是一張「地圖」，不是一排方塊。要有場景感。
- 路徑要蜿蜒（S 形或曲線），不要等距直線排列。
- 棋子是一隻有個性的小動物角色，會眨眼、會呼吸、跳躍時有表情，
  不要只是把 emoji 放進白色圓圈。
- 走過的格子與未走的格子，視覺上要一眼分得出來。

【主題設定】（這一段之後若有覆蓋指示，以覆蓋的為準）
- 標題：森林大冒險
- 場景：森林 —— 畫出地面、草叢、樹木、遠山、天空，有遠近層次。
- 主色：#16a34a（森林綠），同一個綠色系要分出亮部暗部，加上暖色點綴。
- 格子造型：路上的「石板 / 木樁 / 蘑菇」，彼此造型有變化，不要六個一模一樣。
- 題目主題：資安、護眼、密碼、個資、硬體常識。

【玩法】
- 6 個格子：起點 → 4 個問答格 → 1 個 BOSS 格。
- 按「擲骰子」前進 1-3 格，踩到問答格跳出題目卡，三選一。
- 答對得 10 金幣，BOSS 得 50 金幣。
- 答錯不扣分，可以無限重試（低年級不要有挫折感）。
- 抵達終點依金幣數給 1-3 顆星。

【動畫要飽滿】
骰子翻滾、棋子跳躍要有擠壓拉伸、答對要有粒子與金幣飛行、
數字要滾動不要直接跳、BOSS 過關要有彩帶與畫面震動。

=============== 以下是技術約束，請務必遵守 ===============

1. 單一 HTML 檔，所有 CSS / JS 內嵌，不要用任何建置工具或框架。
2. 不要引用任何外部圖片、音效、影片檔。
   插畫請用 inline SVG 或 CSS 繪製；音效請用 Web Audio API 即時合成。
   （唯一允許的外部資源是 Google Fonts 的 Noto Sans TC）
3. emoji 只能使用 2015 年以前就存在的：
   ✅ 🌲 🌱 ❓ 👑 ⭐ 💰 🐰 🎉 🔊
   ❌ 🪙 🪴 🫠 這類 2020 年後的新 emoji
   理由：教室電腦是舊版 Windows，新 emoji 會顯示成空白方塊。
4. 進度存 localStorage，key 一律用這個前綴，不要自己另外取名：
       edtech-board-progress   （JSON：{ pos, coins, done: [] }）
       edtech-board-best       （數字：歷史最高金幣）
5. 必須支援 `@media (prefers-reduced-motion: reduce)`：
   該模式下關閉所有動畫，但遊戲仍要能玩。
6. 版面要有兩套，用 media query 切換，**不是只做其中一套**：
   (a) 橫向寬螢幕（主）：教室投影用，這是設計基準。
   (b) 手機直立（次）：`@media (orientation: portrait)` 底下微調，
       格子與按鈕仍要看得清、點得到，不可橫向捲動。
   ⚠️ 直立版不要用「把整張固定比例畫布縮小」來交差——實測 800×600 畫布
   在 390px 只能縮到 0.49 倍，格子小到低年級點不準。
   直立版可以重排（例如地圖佔上方、控制列固定在下方），
   但**橫向主版面必須維持完整的橫式場景**，不要被直立版帶著走。
7. 字級：題目文字至少 20px，選項至少 18px（一到三年級 + 教室投影）。
   題目用字請控制在低年級識字量：盡量用常用字，長句拆短句，
   必要時用圖示或 emoji 輔助理解。
8. 所有可點擊元素要有 cursor: pointer 與明顯的 hover / 按下回饋。
9. 題目資料請集中成一個 JS 陣列常數 QUESTIONS，
   格式固定為 { q: '題目', opts: ['選項1','選項2','選項3'], a: 正解索引 }，
   方便老師之後自己加題目。
10. 請在程式碼裡加中文註解說明各區塊用途。
11. 彈出視窗關閉時，**不可以只用 opacity:0 + pointer-events:none**。
    那樣裡面的按鈕仍留在鍵盤 Tab 順序與無障礙樹中，使用者可以 Tab 進
    關閉中的視窗按 Enter。請一併加上 visibility:hidden（或 inert）。
12. 星等／評等的門檻要留緩衝：**答錯一題仍應拿得到最高評等**。
    不要把最高門檻剛好設在滿分，否則等於「全對才三星」，低年級會挫折。
13. 面向使用者的可變值（學校名稱、班級、老師姓名等）做成**介面可編輯欄位**，
    不要在程式裡寫死成常數。
14. 請在檔案最前面加一行註解標示區域代號，方便後續整合：
        <!-- ZONE_ID: forest -->   （依實際區域填 forest / ocean / space / castle）

=============== 交件前請自我檢查 ===============

回覆時請在程式碼後面附一份自檢表，逐條列出上面 14 條約束是否做到，
做不到的直接說明原因，不要默默略過。格式：

  1. 單一 HTML 檔 ....................... ✅
  2. 無外部素材 ......................... ✅
  ...
  6. 390px 直立可用 ..................... ❌ 原因：…

（契約版本 v2.1，2026-09-20。
  v1 → v2：補第 11–14 條。
  v2 → v2.1：v2 的第 6 條只寫「為直立螢幕另外配置版面」，
  Canvas 把整體設計改成直立式了。補上【主要使用情境】段落宣告
  橫向為主版面，第 6 條改寫成明確要求兩套 media query 版面。）
```

## 驗收清單（拿回成品後逐條檢查）

視覺（Canvas 的強項，主要看這幾點有沒有做到）
- [ ] 有場景層次（天空／遠山／地面／前景），不是純色背景
- [ ] 路徑蜿蜒，格子造型有變化
- [ ] 棋子是有表情的角色，不是 emoji 放圓圈
- [ ] 走過 / 未走過的格子一眼可分

契約（先跑 `python board/verify-canvas.py <檔案>`，12 項自動檢查）

腳本測不到、要人工看的：
- [ ] 390px 直立**真的能玩**（不只是沒有橫向捲動，格子要點得到）
- [ ] 彈出視窗關閉後無法用 Tab 聚焦到裡面的按鈕
- [ ] 答錯一題仍拿得到最高評等
- [ ] 可變值（校名等）是介面可編輯，不是寫死的
- [ ] 檔頭有 `<!-- ZONE_ID: … -->`
- [ ] Canvas 附的自檢表沒有默默略過任何一條

## 其餘三區怎麼生（海洋／太空／城堡）

森林區已完成。要生下一區時：

1. 先貼上面那段**基礎提示詞**
2. 再貼下面對應區域的**覆蓋區塊**（同一則訊息接著貼即可，不用改任何字）
3. 拿到 HTML 後把檔案路徑給 Claude

**四區的知識主題刻意不重疊**，這樣四區走完才等於完整覆蓋，
而不是同樣的題目換個背景問四次。

## 拿到檔案後 Claude 會做的事

1. 跑 `python board/verify-canvas.py <檔案>`（12 項契約檢查）
2. 瀏覽器確認視覺 6 項與 390px
3. 修不合格處（森林區修過的三項通常會重現：modal Tab 聚焦、星等門檻、直立版面）
4. 接進 `board/index.html` 的 `ZONES`，把該區 `ready` 改成 `true`
5. 首頁補該區卡片、README 與 SDD 同步

## 分工建議

| 誰 | 做什麼 |
|---|---|
| Gemini Canvas | 場景插畫、角色、路徑造型、動畫表現 |
| 蛋糕 | 出題目內容、決定難度與教學目標 |
| Claude | 契約制定、驗收、整合進 repo、修相容性問題、接首頁入口、寫 SDD |

**為什麼要這樣分**：Canvas 一次性生成的視覺強，但不會遵守專案慣例，
也不會考慮教室舊機器、螢幕閱讀器、減少動態這些邊界情況——
那是整合階段要補的。先立契約能讓補的量大幅下降。
