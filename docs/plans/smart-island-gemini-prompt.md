# 給 Gemini 的生成規格（小常識島 6 關）

規劃：`docs/plans/2026-11-21-smart-island-plan.html`；設計規範：`.interface-design/smart-island-system.md`；外殼：`assets/js/smart-ui.js`＋`assets/js/smart-pet.js`＋`assets/css/smart-island.css`；範本：`assets/smart/demo.html`；寵物小屋：`units/smart-pet-house/`。
組提示詞：`python tools/build-smart-island-prompt.py <unit29> <輸出檔>`（共用段＋本關段＋設計規範＋範本）。
交件後：`tools/agy-extract.py` 拆出 HTML → 存成 `units/<資料夾>/index.html` → `python tools/build-smart-font.py <BpmfHuninn ttf>` → 列出注音句渲染核對破音字（教育部《重編國語辭典修訂本》）→ 用下方「審題檢核表」逐題檢查 → `python tools/test-smart-scenes.py <unit>` → 實際操作截圖、對照本關「學習能力」。
教學理論：使用者 11-21 選「對應學習能力＋審題檢核＋ARCS」（分層提示、Gagné 沒選，不硬加）。寬鬆過關沿用畫畫島。

## 共用提示詞

```
【回覆方式】不要使用任何工具：不要建立或寫入檔案、不要執行指令、不要讀取資料夾。
直接把完整程式碼寫在你的文字回覆裡，用一個 ```html 區塊包住整個檔案，區塊後面附「題目檢核表」與「自檢表」。

你要為台灣國小（1–4 年級）資訊常識遊戲「小常識島」寫其中一關的網頁 index.html。
小常識島的主軸是「數位寵物養成」：孩子在寵物小屋領養一隻寵物（雲朵兔、鍵盤龜、螢幕貓、燈泡雞），每過一關拿點心餵牠，集滿會長大。
這次你只負責「遊戲場景」：出題、互動、寵物在旁陪伴。開始畫面、關卡卡片、頂欄（首頁、題號進度、寵物頭像）、答對答錯回饋卡、
結算畫面（寵物吃點心、成長條、回顧、交成績）、存檔、寵物圖，全部由已經寫好的共用程式 smart-ui.js／smart-pet.js 處理，你不要重寫它們，也不要改它們的樣式。
你的工作是把這一關做得「好玩、可愛、一看就懂」，題目要正確、合乎國小生活情境，並且正確地接上共用程式。

<!doctype html><html lang="zh-Hant"><head>

body 裡不要放其他 HTML：畫面由 SmartIsland.mount 產生。

【mount 要填的欄位】
unit、title、grade、howto、zhuyin、teach 照【本關設定】一字不改；
levels：照本關設定的關卡名稱，每關一個 icon（inline SVG 字串，40×40 viewBox，線條 #3B2350 粗 2.6、可愛簡單，畫這關的主題）。

【共用程式給你的 api（scene 函式收到的參數）】
- api.field：場景容器 div，固定 1366×591 px（在 66px 頂欄下方），舞台會自動等比縮放，可以用 px 絕對定位
- api.progress(i, n)：頂欄右側顯示「第 i 題／共 n 題」＋進度豆（i 從 1 起算），每出一題呼叫一次
- api.petSVG(mood, opts)：孩子自己那隻寵物的 SVG 字串（沒領養時是訪客小雲）；mood：'happy'｜'normal'｜'worried'｜'surprised'；
    opts：{ q:true 頭上冒問號, sweat:true 流汗, spark:true 冒星星 }。場景裡要讓寵物陪在旁邊（約 260–320px 大），出題時用 normal＋q，
    孩子想的時候寵物可以說一句話（對話泡泡用你自己的 sc- 樣式）
- api.pet()：{ name, type, stage, guest }，可以在台詞裡叫寵物的名字（例「小雲收到一則訊息」）
- api.feedback({ ok, text, explain, zyExplain }) → Promise：跳出寵物回饋卡（對＝開心＋✓，錯＝擔心＋✗），孩子按「下一題」才 resolve，
    ok：對或錯；text：主句，省略就用預設句（注音關的預設句已核對過讀音，建議省略）；
    explain：一句正確觀念（**答錯時一定要給**，答對也可以給一句加深印象）；zyExplain：true＝explain 用注音字型（1–2 年級的關要設 true）
    用法：api.feedback({ ok: false, explain: '滑鼠可以移動游標。', zyExplain: true }).then(下一題)
- api.finish({ stars, review, learned, retry })：完成這一關
    stars：0–3（規則見本關設定；外殼會保底 1 顆）；review：[{ ok, q }] 每題的對錯與題目短句；
    learned：今天學到的一句話（具體、正面、12–20 字，例「不認識的人要照片，一定不給」）；retry：答錯時一句要再練習的提醒（全對可省略）
- api.zy：這關是否用注音；場景裡給 1–2 年級讀的句子（題目、選項文字、寵物台詞）加 class="sm-zy"
- api.levelIndex()：目前第幾關（0 起算）；api.toSetup()：回開始畫面

【scene 函式要回傳的物件】
{ start(levelIndex),  // 進入某一關時呼叫：清空 api.field，從第 1 題開始
  stop() }            // 離開這關時呼叫：停掉所有 requestAnimationFrame、setTimeout、setInterval、移除 document 上的監聽，並讓還沒 resolve 的 feedback 之後什麼都不做
同一個 scene 物件會被重複 start 不同關，每次 start 都要從乾淨的狀態開始。

【畫面風格 — 一定照附件的設計規範 smart-island-system.md】
黏土點心屋風：桃杏奶油底、卡片和按鈕像厚厚的黏土玩具。用規範的色票變數（var(--orange)、var(--violet)、var(--ok)、var(--bad) 等）
與共用 class（.clay 黏土卡、.sm-btn、.sm-btn.or、.sm-btn.vi、.chip、.sm-zy、.sm-num），不要另外發明介面主色。
版面參考附件 demo.html：左／中題目區＋選項卡，右側寵物陪伴。題目區要乾淨，裝飾不能干擾讀題。
情境圖（書桌、手機畫面、聊天視窗、房間）都用 inline SVG 或 CSS 畫，不要外部圖片；不要用 emoji 當圖示或主要圖案（Windows 上會變醜）。

【教學設計 — 一定要做到】
1. 對應學習能力：本關設定的「學習能力」每一條都要有題目練到（題目檢核表要寫出哪題對哪條）
2. ARCS 動機設計：
   A 注意：每關開場用寵物的情境帶入（例「小雲的新電腦送來了！」），題目都是寵物遇到的事
   R 關聯：情境取自國小生活（家裡、教室、平板、手機、聊天群組），不要成人職場情境
   C 信心：每關第 1 題最簡單，難度一題一題慢慢加；答錯不扣分、不擋關（見寬鬆過關）
   S 滿足：答對時寵物開心＋一句具體稱讚；結算的 learned 寫出孩子學會的那件事
3. 寬鬆過關（老師特別要求，最優先）：答錯也一定能往下一題，整關做完一定呼叫 api.finish（最少 1 顆星）；
   不要有「答錯就重來／扣命／Game Over／計時到就失敗」的設計。拖曳類放錯，就讓物件彈回並提示一句，孩子可以再放
4. 每題答錯時給一句「正確觀念」（explain），不是只說「錯了」；語氣溫和，像寵物在跟主人說話

【出題規則 — 審題檢核（交件後老師會逐題檢查，不合格要重做）】
題幹：
- 一題只問一件事，對得上一條學習能力；不看選項也知道在問什麼
- 不用否定題幹（「哪一個不對」）；真的要用時，「不」字加粗並換色
- 題目之間互相獨立，不能從一題看出另一題的答案
- 題目要寫正確的資訊常識；有爭議或「看情況」的做法不要出
選項：
- 只有一個最好的答案（判斷題只有「好／不好」或「安全／危險」兩個選項時，答案也要明確，不能兩可）
- 每題 3 個選項（另有規定的照本關設定）；選項長度、語氣、詳細程度差不多，正解不要特別長、特別完整
- 每個錯誤選項都要對應一個孩子真的會有的想法（迷思），寫在題目資料的 why 欄位，不要放明顯好笑、沒人會選的選項
- 不用「以上皆是」「以上皆非」
- 正解位置要分散：同一關裡正解在第 1、2、3 個的次數大致平均，不能有規律（例如不能都是第 2 個、不能 1-2-3-1-2-3）；
  選項順序寫死在資料裡（不要隨機洗牌），題目檢核表才對得起來
整關：
- 難度：多數是孩子用心想就答得出來的題（目標答對率約 7–9 成），每關最後 1–2 題可以稍難
- 不要沿用下面「大富翁港已經出過的題目」的題幹與情境（同一個觀念可以換情境、換問法）：
  ・網路上看到「恭喜你中獎了！點擊領取免費手機」怎麼做　・保護眼睛，用電腦或平板多久要休息一下
  ・哪一個是好密碼　・玩遊戲時不認識的人要真實姓名和學校　・哪一個是電腦的大腦（主機／CPU）
  ・生日卡片圖片要存在哪裡　・資料夾的主要功能　・不小心刪除的檔案跑去哪裡、可以找回來嗎
  ・為什麼要幫檔案取清楚的名字　・電腦快壞掉時怎麼防止檔案不見（備份）
- 題目資料集中寫在檔案開頭的常數 SCENE_CONFIG.LEVELS，每題格式：
  { q: '題目', options: [{ text: '選項', pic: '可選的SVG鍵名' , why: '選這個的孩子在想什麼（正解寫「正解」）' }, …], ans: 正解索引(0起算), explain: '一句正確觀念' }

【給小朋友用（老師特別要求）】
- 1366×657 一屏放得下，不能捲動；選項卡、按鈕都 ≥ 44px，1–2 年級的選項卡至少 200×160
- 介面文字 ≥ 16px，一般 20–24px；按鈕字不能斷行（white-space: nowrap）
- 1–2 年級的關（zhuyin: true）：題目、選項文字、寵物台詞都加 class="sm-zy"（注音字型，字寬約 1.35 倍），句子短（12 字內最好）、用圖片輔助；
  注音句的框要容得下整句，不要讓句子斷在詞中間；不要自己用 <ruby> 標注音
  注音字型是照字畫讀音，所以用字盡量避開破音字：得、著、地（當「的」用）、還、長、重、行、樂、名字、衣服、東西、什麼、看看、一下、我們；
  老師交件後會逐句核對讀音，有問題的句子會請你改寫
- 對錯不能只靠紅綠：同時用 ✓ ✗ 或文字（回饋卡已經做好）
- 護眼：不連續閃爍（每秒 ≤ 3 次）；動畫只在回饋瞬間；prefers-reduced-motion 時關掉動畫
- 好玩：題目包在寵物的小故事裡；選到之前寵物可以歪頭、冒問號

【技術約束】
1. 單一 HTML，只能引用骨架裡的檔案和 Google Fonts；不要 import 其他函式庫
2. 場景所有元素都放在 api.field 裡；不要動 document.body 的其他內容，不要改 .sm- 開頭的任何樣式
3. 不要自己做存檔、星星、結算畫面、答對答錯彈窗、交成績、回首頁按鈕、寵物繪圖（共用程式都做了）
4. 點選用 click；拖曳一律用 pointer events（pointerdown／pointermove／pointerup），要 setPointerCapture，被拖的元素加 touch-action: none；
   舞台有 CSS transform 縮放，算座標時用 getBoundingClientRect() 的實際寬高比例換算回 px
5. 同一題作答後立刻鎖住選項（避免連點兩次），等 feedback 的 Promise resolve 再出下一題
6. 程式碼加中文註解；題目、星星門檻集中在檔案開頭的具名常數 SCENE_CONFIG
7. 介面文字一律繁體中文、台灣用語

【回覆最後的「題目檢核表」— 每一題一列】
| 關 | 題 | 題目 | 正解位置(1/2/3) | 對應學習能力 | 錯誤選項 A 的迷思 | 錯誤選項 B 的迷思 | 難度(易/中/稍難) |
最後寫：每關正解位置的次數（例 第 1 關：1→2 次、2→2 次、3→1 次）、有沒有跟大富翁港題目重複

【回覆最後的「自檢表」— 逐條寫「有／沒有」並說明】
- 是否完全照骨架、只寫場景？mount 欄位是否照本關設定一字不改？
- 每關都有呼叫 api.progress、答錯都有 explain、最後都有 api.finish（含 review、learned）嗎？星星規則跟本關設定一樣嗎？
- 答錯是否一定能往下（寬鬆過關）？有沒有任何扣命、計時失敗、重來的設計？
- stop() 是否清掉所有動畫、計時器與 document 監聽？重複 start 是否從乾淨狀態開始？
- 1366×657 是否一屏不捲動？選項與按鈕是否 ≥ 44px？注音句有沒有斷在詞中間？
- 寵物有沒有陪在畫面上？ARCS 四項各在哪裡做到？
- 有沒有用 emoji 當圖示、<ruby>、外部圖片或其他函式庫？
```

## 本關設定

### unit29（寵物的新電腦）

```
【本關設定】資料夾 units/unit29-pet-computer/
mount：unit: 29, title: '寵物的新電腦', grade: '1–2 年級', zhuyin: true,
  howto: '寵物買了新電腦！請你幫牠找出滑鼠。',
  teach: '認識常見的資訊設備與用途｜資E1 認識常見的資訊系統'
levels（3 關，每關 5 題）：書桌上的電腦、設備小幫手、家裡的資訊產品

【玩法】
- 第 1 關「書桌上的電腦」：畫一張大書桌場景（螢幕、鍵盤、滑鼠、主機、耳機、喇叭，SVG 畫、每個都能點，感應區至少 96×80），
  題目「滑鼠在哪裡？」這類，孩子直接點場景裡的設備作答（這關是點場景，不是 3 選 1 卡片）；點錯就回饋「這是耳機」這類，explain 說正確的那個設備長怎樣或做什麼
  第 1 題固定用「滑鼠在哪裡？」（跟開始畫面玩法句呼應）
- 第 2 關「設備小幫手」：寵物想做一件事（想聽音樂、想打字、想看影片、想把圖畫印出來、想跟奶奶視訊），從 3 張設備圖卡選要用哪個
  （耳機、鍵盤、螢幕、印表機、視訊鏡頭、麥克風…），錯誤選項要是孩子會搞混的設備（例：想聽音樂 → 麥克風 vs 耳機）
- 第 3 關「家裡的資訊產品」：找出哪一個是資訊產品（平板、手機、智慧手錶、電腦）或哪一個不是（書本、鉛筆、積木），
  也可以問「哪一個可以上網查資料」；用 3 張圖卡
- 題目、選項文字、寵物台詞都用 class="sm-zy"；圖卡以圖為主、字為輔

【星星】該關 5 題答對 5 題 → 3 顆；3–4 題 → 2 顆；0–2 題 → 1 顆
【學習能力】
1. 說出電腦的基本設備：螢幕、鍵盤、滑鼠、主機、耳機／喇叭
2. 知道常見設備的用途（輸入、輸出：打字、點選、看、聽、印）
3. 認出生活中的資訊產品（電腦、平板、手機、智慧手錶）
```

### unit30（寵物作息表）

```
【本關設定】資料夾 units/unit30-pet-schedule/
mount：unit: 30, title: '寵物作息表', grade: '1–2 年級', zhuyin: true,
  howto: '幫寵物排好一天，用平板也要愛護眼睛！',
  teach: '健康使用 3C：坐姿、護眼、作息｜資E11 建立康健的數位使用習慣與態度'
levels（3 關，每關 5 題）：坐好看螢幕、愛護眼睛、寵物的一天

【玩法】
- 第 1 關「坐好看螢幕」：3 張寵物用電腦或平板的姿勢圖（坐正、背靠椅背、腳踩地 vs 駝背貼近螢幕 vs 躺在床上、趴著），選「哪一個坐得最好？」；
  也可以問螢幕要放多遠（用圖示意：太近、剛好、手伸直的距離）
- 第 2 關「愛護眼睛」：眼睛累了怎麼辦（看遠方的綠樹、閉眼休息 vs 揉眼睛 vs 把螢幕調更亮）、在暗暗的房間用平板好不好、
  走路時看手機好不好；**不要問「多久要休息一下」（大富翁港已經出過）**
- 第 3 關「寵物的一天」：寵物放學後的時間表（寫功課、玩平板、運動、吃飯、睡覺）用時間軸卡片呈現，題目判斷安排好不好，
  例「睡覺前一直玩平板，好不好？」→ 好／不好兩個大按鈕（這關可以是 2 選 1，按鈕上要有 ✓／✗ 圖示和字）；也可以問「玩完平板接下來做什麼最好」（3 選 1）
- 題目、選項文字、寵物台詞都用 class="sm-zy"
