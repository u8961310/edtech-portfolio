聖誕工坊大救援

聖誕夜前一晚，工坊的送禮電腦當機了。學生扮演小精靈「叮叮」，帶著麋鹿「雪球」闖過四關，把電腦修好、在天亮前把禮物送完。每關先玩一段小遊戲，再答兩題闖關題。

對象

四個關卡

以好玩為主：每關的小遊戲占大部分時間，闖關題穿插在過關前，答錯可以重答，不扣分。每關各練一種資訊能力，剛好對上中年級的資訊課。

關卡小遊戲玩法練到的能力闖關題
① 包裝產線工坊一樓輸送帶送來禮物，看標籤上的特徵（形狀、顏色、會不會發光），拖進對的箱子。速度慢慢加快。資料分類、依特徵歸組；滑鼠拖曳2 題
② 雪橇導航屋頂起飛用箭頭積木排出雪橇路線，經過煙囪、避開暴風雪雲。後面幾題要用「重複 3 次」積木才排得下。程式序列、重複、除錯2 題
③ 願望信箱收信室小朋友的願望信裡混了怪信：「點這裡送免費點數」「告訴我你家地址」。把怪信丟進碎紙機，真的願望信放進禮物袋。網路安全、個資保護、辨識詐騙2 題
④ 夜空送禮BOSS 關雪橇飛過屋頂，每根煙囪上浮著一個字，打出來就把禮物丟進去。可以切換英打／注音。最後要過「暴風雪大魔王」的快問快答。打字（英打或注音）、綜合複習5 題
合計四關，一輪約 15～20 分鐘11 題

星星門檻留緩衝：錯一兩題（重答後才對）仍拿得到三顆星，照大富翁的規範，不做「全對才三星」。

題目集中放在一個 QUESTIONS 陣列，每題標好關卡，老師之後可以自己換題。用字控制在中年級識字量，句子短，能配圖就配圖。

製作流程：Gemini Canvas 做遊戲，我負責接進網站

沿用大富翁那套已經驗證過的做法：我先寫好給 Canvas 的提示詞和交件規格，你在 Gemini Canvas 裡生成、調畫面，滿意後請它給「完整的單一 HTML」，存成檔案交給我整合。遊戲本身不連 AI，放在 GitHub Pages 就能跑。

  1. 我寫 units/CANVAS_PROMPT-xmas.md：故事、四關玩法、題庫格式，加上大富翁 v3 規格裡適用的條款
  2. 我把 board/verify-canvas.py 改成單元也能用，加檢查：有沒有存 edtech-unit22-score
  3. 你把提示詞貼進 Gemini Canvas 生成第一版，看畫面、玩一輪，直接在 Canvas 裡請它改
  4. 你滿意後請 Canvas 給完整單一 HTML，存成 xmas.html 給我（分享連結不行：沒辦法放進網站，而且拿到連結的人都能改）
  5. 我跑驗收腳本＋開瀏覽器實玩（投影寬螢幕、375 手機、console 零錯誤），有問題列清單讓你回 Canvas 修
  6. 我整合上架（見下一節清單），部署、正式網址端對端驗證

交件規格重點（寫進提示詞）

  • 橫向投影為主版面（約 1280×800），手機直立另外用 media query 調整，不要整個改成直式
  • 單一 HTML、不引用外部圖片和音效：雪花、禮物、麋鹿都用 SVG／CSS 畫，音效用 Web Audio 合成，字型只用 Noto Sans TC
  • 只用舊版 Windows 顯示得出來的 emoji：🎄 🎁 ⭐ 🔔 ⛄ ❄ 可以用；2020 年後的新 emoji 不行
  • 分數存 edtech-unit22-score，首頁徽章才會亮（unit13～21 有 6 個就是漏了這條）
  • 題目字級至少 20px、選項至少 18px；答錯可重答、不扣分
  • 不做姓名、學校、班級欄位，也不做證書
  • 支援減少動態（prefers-reduced-motion）；彈窗關閉要加 visibility:hidden；交件前 console 零錯誤
  • 角色是原創：小精靈叮叮、麋鹿雪球，不用任何卡通或電影裡的現成角色和歌曲

需要你決定的事

1
名字和角色可以嗎？「聖誕工坊大救援」、小精靈叮叮、麋鹿雪球，都可以換。
2
BOSS 關的打字要用哪種？英打、注音，或兩種都做讓老師切換。建議：雙模式，三年級多半還在練注音，四年級可以挑戰英打。
3
放在學習樂園島的哪裡？新開一座「節慶島」，之後春節、兒童節的遊戲也有地方放；或塞進現有的小常識島（目前只有 2 關）。建議：新開節慶島，要多重產一次島嶼圖。
4
四關會不會太多？一節課 40 分鐘，扣掉說明約可玩兩輪。想更短的話可以砍成三關（拿掉包裝產線）。
