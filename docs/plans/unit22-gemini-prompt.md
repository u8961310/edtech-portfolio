## 提示詞

```
【回覆方式】不要使用任何工具：不要建立或寫入檔案、不要執行指令、不要讀取資料夾。
直接把完整程式碼寫在你的文字回覆裡。

請做一個給台灣國小三、四年級學生的聖誕節網頁遊戲「聖誕工坊大救援」，單一 HTML 檔。
以「好玩」為第一優先，闖關題穿插在小遊戲之間。

【主要使用情境 — 先讀這段再設計版面】
最主要的用法是老師在教室用單槍投影示範，學生再用教室電腦各自玩。
所以橫向寬螢幕是主版面（約 1280×800），請以它為設計基準。
手機直立是次要情境，用 CSS media query 另外調整即可，不要把整體設計改成直立式。

【故事】
聖誕夜前一晚，聖誕工坊的送禮電腦當機了。玩家扮演小精靈「叮叮」，
和麋鹿「雪球」一起闖過四關，把電腦修好，在天亮前把禮物送完。
叮叮與雪球是原創角色：請自己設計造型（手繪風 SVG），要有表情、會眨眼、
過關會開心跳起來。不要使用任何卡通、電影裡的現成角色或聖誕歌曲旋律。

【畫面風格 — 這是重點】
- 每一關都是一個「場景」，不是一排按鈕：工坊一樓、屋頂、收信室、夜空，
  各有自己的背景層次（遠景、中景、前景），飄雪貫穿全程。
- 主色：聖誕紅 #c0392b、松樹綠 #1e7a4c、暖金 #e6a817，夜空關用深藍。
  同色系要分出亮暗部，不要整片純色。
- 開場有標題畫面＋一句故事＋「開始救援」大按鈕；關卡之間有簡短過場（雪球拉雪橇飛過）。
- 畫面上方常駐：目前第幾關（4 個小燈泡，過關的會亮）、星星數、音效開關。

【聖誕（耶誕）風格要貫穿整個畫面 — 不只是背景】
一打開就要讓人覺得「聖誕節到了」，每個介面元件都要有聖誕元素，不要只有背景放一棵樹：
- 場景道具：聖誕樹（掛彩球、頂端星星）、閃爍的彩色燈串、花圈、拐杖糖、薑餅人、
  聖誕襪、槲寄生、壁爐、雪人、覆雪的屋頂與窗戶透出暖黃燈光。
- 介面元件：
  按鈕做成「禮物盒」或「拐杖糖紅白斜紋」造型；題目卡做成「聖誕卡片」（雙層邊框＋角落冬青葉與紅果）；
  標題用帶白色積雪的字（字上方覆一層雪）；分隔線用燈串或冬青葉；
  進度燈泡是聖誕燈泡造型（紅綠金交替），過關時亮起並微微閃爍。
- 質感：紅綠格紋（tartan）當局部底紋、金色亮點與閃光、柔和的暖光暈；
  夜空關要有滿天星、月亮、遠方小鎮的燈火。
- 氣氛：開場與結局響起鈴鐺叮噹聲（Web Audio 合成，原創音型，不要用現成聖誕歌旋律）；
  結局畫面放煙火般的金色雪花與彩帶。
- 文字用語用台灣習慣：「聖誕節」「聖誕老公公」「聖誕快樂」。

【四個關卡】
每關流程：小遊戲 → 闖關題（第 1～3 關各 2 題，第 4 關大魔王 5 題）→ 過關動畫。
闖關題三選一，答錯會溫和提示「再想想看」並可以重答，不扣分、不結束遊戲。

① 包裝產線（資料分類）
  輸送帶送來禮物，每個禮物有 2 個看得見的特徵（形狀：方／圓；顏色：紅／綠），
  畫面下方有 3～4 個貼了條件標籤的箱子（例如「紅色的」「圓的」「綠色而且方的」）。
  學生用滑鼠把禮物拖進正確的箱子。共 8 個禮物，後面越來越快。
  放錯箱子禮物會彈回輸送帶，不扣分。拖曳也要支援觸控（pointer events）。

② 雪橇導航（程式序列、重複）
  6×6 的屋頂格子地圖，雪球在起點，要經過 1～2 根煙囪，避開暴風雪雲。
  學生點「↑ ↓ ← →」與「重複 2 次」「重複 3 次」積木排出程式（最多 8 格），按「出發」執行，
  雪橇照指令一步一步走。撞到雲或走出地圖就停下，提示「哪一步要改？」，可以修改再試。
  共 3 張地圖，第 3 張的步數一定要用「重複」積木才排得下。

③ 願望信箱（網路安全、個資保護）
  信件一封一封送來（共 8 封），學生判斷：真的願望信 → 拖進禮物袋；
  怪信 → 拖進碎紙機。怪信例如：「點這裡送你免費遊戲點數」「告訴我你家住址和電話」
  「把爸媽的密碼給我就送你禮物」「你中獎了！快輸入帳號」。
  真的願望信例如：「我想要一本恐龍書」「希望阿嬤身體健康」。
  判斷錯了，叮叮會用一句話解釋為什麼。

④ 夜空送禮（打字＋大魔王）
  雪橇飛過夜空，下方屋頂一根一根煙囪捲過來，煙囪上浮著一個詞。
  學生在輸入框打出那個詞，按 Enter 就把禮物丟進煙囪。共 10 個詞。
  一開始讓老師／學生選模式：
    「英文模式」：gift、star、snow、tree、bell、cake、card、sock、moon、home 這類 3～4 字母單字
    「注音模式」：禮物、雪人、星星、鈴鐺、蛋糕、卡片、襪子、月亮、聖誕樹、麋鹿
  注音模式學生會用 Windows 注音輸入法打字，必須處理 IME：
    監聽 compositionstart / compositionend，組字中（isComposing）不要比對、不要清空輸入框，
    組字完成後才比對；比對前去掉前後空白。
  沒打中的煙囪只是飛走，不扣分。打完 10 個詞後「暴風雪大魔王」出現，進入 5 題快問快答，
  每答對一題大魔王縮小一點，5 題答完雪停、天亮、禮物送完，播放結局動畫。

【闖關題】
- 共 11 題，集中成一個 JS 陣列常數 QUESTIONS，格式固定為
  { stage: 1, q: '題目', opts: ['選項1','選項2','選項3'], a: 正解索引 }
  方便老師之後自己換題。用字控制在中年級識字量，句子短。
- 題目方向：
  第 1 關（分類、檔案）：照片放哪個資料夾、怎麼替檔案取名才找得到
  第 2 關（程式）：重複指令的意思、程式出錯時怎麼找錯的那一步
  第 3 關（網路安全）：陌生人要密碼怎麼辦、看到「免費送點數」連結怎麼辦
  第 4 關大魔王（綜合）：哪個密碼最安全、在網路上可以說出自己的住址嗎、
    玩電腦多久要休息、看到同學被網路霸凌要找誰、網路上的圖片可以隨便拿來用嗎

【計分與星星】
- 每關依表現給 1～3 顆星，全遊戲最高 12 顆。門檻要留緩衝：
  有一兩次放錯或答錯（重答才對）仍然要拿得到 3 顆星，不要做成「全對才三星」。
- 結局畫面顯示總星數，並鼓勵一句話。可以「再玩一次」。

【動畫與音效】
飄雪、禮物拖曳時有晃動、放對箱子有閃光、雪橇轉彎有傾斜、答對有星星飛向上方星星欄、
數字滾動不要直接跳。音效用 Web Audio API 即時合成（叮噹聲、答對、答錯的溫和音），
預設開啟，右上角可以關閉。

=============== 以下是技術約束，請務必遵守 ===============

1. 單一 HTML 檔，所有 CSS / JS 內嵌，不要用任何建置工具或框架。
2. 不要引用任何外部圖片、音效、影片檔。插畫用 inline SVG 或 CSS 繪製；音效用 Web Audio API 合成。
   唯一允許的外部資源是 Google Fonts 的 Noto Sans TC。
3. emoji 只能使用 2015 年以前就存在的，例如：🎄 🎁 ⭐ 🔔 ⛄ ❄ 🎅 🦌 ✉ 🏠 🌙 🔊 🔇
   不要用 🪅 🫶 🧑‍🎄 這類 2019 年後的新 emoji（教室是舊版 Windows，會變空白方塊）。
4. 成績存 localStorage，key 一律用這個前綴：
       edtech-unit22-score      （數字：歷史最高總星數 0～12，只在打破紀錄時更新）
       edtech-unit22-progress   （選用，JSON：目前關卡與各關星數，可以中途離開再回來）
   讀寫 localStorage 都要包 try/catch，讀不到就當新遊戲。
5. 必須支援 @media (prefers-reduced-motion: reduce)：該模式下關閉所有動畫（含飄雪），遊戲仍要能玩。
6. 版面兩套，用 media query 切換：
   (a) 橫向寬螢幕（主）：教室投影用，設計基準。
   (b) 手機直立（次）：@media (orientation: portrait) 底下重排，按鈕與拖曳目標仍要夠大，不可橫向捲動。
   直立版不要用「整張固定比例畫布縮小」交差。
7. 字級：題目至少 22px、選項至少 20px、一般說明至少 18px（中年級＋教室投影）。
8. 所有可點擊、可拖曳的元素要有 cursor: pointer（拖曳用 grab）與明顯的 hover／按下回饋。
9. 彈出視窗（題目卡、提示）關閉時，不可以只用 opacity:0 + pointer-events:none，
   要一併加上 visibility:hidden（或 inert），避免鍵盤 Tab 還能按到裡面的按鈕。
10. 不要做姓名、學校、班級的輸入欄位，也不要做證書。
11. SVG 的 points 屬性只接受數字，不接受百分比。
12. 若用「固定 px 畫布＋JS 算 scale 縮放」，那個固定尺寸的盒子必須加 flex-shrink: 0。
13. 交件前 console 不能有任何錯誤。
14. 程式碼加中文註解說明各區塊用途；面向使用者的文字集中成常數，方便老師修改。
15. 左上角留 120×44px 的空白不要放東西（整合時會放「回首頁」按鈕）。

(2) 程式碼後面附自檢表，逐條列出上面 15 條技術約束是否做到，做不到的說明原因。
