# 給 Gemini 的生成規格（畫畫島 6 關）

規劃：`docs/plans/2026-11-21-art-island-plan.html`；設計規範：`.interface-design/art-island-system.md`；外殼：`assets/js/art-ui.js`＋`assets/css/art-island.css`；範本：`assets/art/demo.html`。
組提示詞：`python tools/build-art-island-prompt.py <unit24> <輸出檔>`（共用段＋本關段＋設計規範＋範本）。
交件後：存成 `units/<資料夾>/index.html` → `python tools/subset-bpmf-font.py <BpmfHuninn ttf> assets/art bpmf-huninn-art.woff2`（字集要涵蓋所有關的注音句，見下方「字型子集」）→ `python tools/test-art-scenes.py <unit>` → 對照本關「學習能力」逐條檢核。
教學理論：使用者 11-21 只選「每關對應學習能力」，所以這份不要求 Gagné／分層提示／ARCS；遊戲內引導以好玩為主。

## 共用提示詞

```
【回覆方式】不要使用任何工具：不要建立或寫入檔案、不要執行指令、不要讀取資料夾。
直接把完整程式碼寫在你的文字回覆裡，用一個 ```html 區塊包住整個檔案，區塊後面附一張「自檢表」逐條回答最後的檢查清單。

你要為台灣國小（1–4 年級）畫畫遊戲「畫畫島」寫其中一關的網頁 index.html。
這次你只負責「遊戲場景」：開始畫面、關卡卡片、頂列（首頁、我的畫廊）、完成畫面（星星、下載、列印、交成績）、畫廊、存檔，
全部由已經寫好的共用程式 art-ui.js 處理，你不要重寫它們，也不要改它們的樣式。
你的工作是把這一關的玩法做得「好玩、可愛、一看就懂」，並且正確地接上共用程式。

【頁面結構 — 一定照這個骨架】
<!doctype html><html lang="zh-Hant"><head>
  <meta charset="utf-8"><meta name="viewport" content="width=device-width, initial-scale=1">
  <title>（本關名稱）- 畫畫島</title>
  <link rel="preconnect" href="https://fonts.googleapis.com">
  <link rel="stylesheet" href="https://fonts.googleapis.com/css2?family=Chiron+GoRound+TC:wght@700;900&family=Noto+Sans+TC:wght@400;500;700;900&family=Fredoka:wght@600;700&display=swap">
  <link rel="stylesheet" href="../../assets/css/art-island.css">
  <style> /* 只放場景樣式，class 一律用 sc- 開頭 */ </style>
</head><body>
  <script src="../../assets/js/art-ui.js"></script>
  <script> ArtIsland.mount({ ...見【本關設定】..., scene: function (api) { ...你的場景... } }); </script>
  <script defer src="../../assets/js/beacon.js"></script>
</body></html>
body 裡不要放其他 HTML：畫面由 ArtIsland.mount 產生。

【mount 要填的欄位】
unit、title、grade、howto、zhuyin、teach、submit 照【本關設定】一字不改；
hero：開始畫面左側的主角插圖（inline SVG 字串，約 380×360，有臉、可愛，粗墨藍輪廓 #1F2A4D）；
levels：照本關設定的關卡名稱，每關一張 thumb（inline SVG 字串，120×120 正方形縮圖，畫這關要做的東西）。

【共用程式給你的 api（scene 函式收到的參數）】
- api.field：場景容器 div，固定 1366×595 px（在 62px 頂列下方），整個舞台會自動等比縮放，所以你可以用 px 絕對定位
- api.quest(text)：設定頂列中間的黃色任務條（例「訂單 3／5：修好蝴蝶的右邊翅膀」），空字串＝不顯示
- api.canvas(容器, { width, height, color, size, mirror })：建立共用自由畫布（白底、滑鼠＋觸控、自動處理縮放），回傳
    { el(canvas 元素), ctx, setColor(c), setSize(px), setTool('pen'|'eraser'), setMirror(fn|null), undo(), clear(), strokes(), onStroke(fn), toDataURL() }
    mirror：fn(點) → 額外要同時畫的點陣列（例：左右對稱 p => [{ x: W - p.x, y: p.y }]）
    onStroke(fn)：每畫完一筆呼叫 fn({ path:[{x,y}…], tool, color, size })
  需要自由手繪的關一定用 api.canvas，不要自己寫畫筆；不需要手繪的關（例如調色鍋、像素格）可以不用
- api.finish({ stars, image, praise, caption, title })：完成這一關
    stars：0–3（規則見本關設定）；image：一個 canvas 元素或 dataURL，**一定要給**，這張圖會進畫廊、可以下載和列印
    praise：一句具體的稱讚（說出孩子做到了什麼，例「紅和黃混成漂亮的橘色！」）；caption：作品名稱（預設＝關卡名）
- api.levelIndex()：目前第幾關（0 起算）
- api.toSetup()：回開始畫面

【scene 函式要回傳的物件】
{ start(levelIndex),  // 進入某一關時呼叫：清空 api.field，建立這關的畫面
  stop() }            // 離開這關時呼叫（回開始畫面、開畫廊、重玩）：停掉所有 requestAnimationFrame、setTimeout、setInterval、移除 document 上的監聽
同一個 scene 物件會被重複 start 不同關，每次 start 都要從乾淨的狀態開始。

【畫面風格 — 一定照附件的設計規範 art-island-system.md】
貼紙畫冊風：湖水綠點點底、粗墨藍輪廓（3px #1F2A4D）、硬陰影（往下位移、不模糊）、白畫布貼黃色膠帶。
用規範的色票變數（var(--blue)、var(--sun)、var(--ok-dk) 等）與共用元件 class（.ai-btn、.ai-btn.go、.ai-panel、.ai-board、.ai-tape、.ai-badge、.ai-zy、.ai-num），不要另外發明介面主色；
顏料、色盤、畫作本身的顏色不受限制。白畫布永遠是畫面主角，裝飾不能搶畫布。
版面參考：左工具面板約 226px、中間白畫布最大、右側任務／模式／「完成」大按鈕（附件 demo.html 就是這個版面）。
角色、物件都用 inline SVG 或 CSS／canvas 畫，不要外部圖片；不要用 emoji 當圖示或主要圖案（Windows 上會變醜）。

【寬鬆過關（老師特別要求，最優先）】
做不對也一定讓孩子過關：任何「不對就不能完成／按鈕不給按／return 擋下來」的設計都不要做。
做得不夠好時照樣呼叫 api.finish，只是星星少（最少 1 顆），稱讚句先肯定、再用一句話說出正確做法（例「綠色是黃＋藍，下次試試看！」）。
唯一可以先提醒、不呼叫 finish 的情況：畫布或作品完全空白（什麼都還沒做）。

【給小朋友用（老師特別要求）】
- 1366×657 一屏放得下，不能捲動；工具、色塊、按鈕都 ≥ 44px（平板手指點得到）
- 介面文字 ≥ 16px，一般 18–20px；按鈕字不能斷行（white-space: nowrap）
- 1–2 年級的關：說明句用 class="ai-zy"（注音字型），句子短、用圖示輔助；不要自己用 <ruby> 標注音
- 對錯不能只靠紅綠：同時用 ✓ ✗ 或文字
- 護眼：不連續閃爍（每秒 ≤ 3 次），做錯用搖一下＋表情，不要滿版閃紅；動畫只在回饋瞬間；prefers-reduced-motion 時關掉動畫
- 好玩：做對要有讓小朋友開心的回饋（角色跳一下、冒星星、小動物道謝），做錯也要好笑不要挫折

【技術約束】
1. 單一 HTML，只能引用骨架裡的檔案和 Google Fonts；不要 import 其他函式庫
2. 場景所有元素都放在 api.field 裡；不要動 document.body 的其他內容，不要改 .ai- 開頭的任何樣式
3. 不要自己做存檔、星星畫面、下載、列印、畫廊、交成績、回首頁按鈕（共用程式都做了）
4. 滑鼠與觸控一律用 pointer events（pointerdown／pointermove／pointerup），拖曳要 setPointerCapture；被拖的元素加 touch-action: none
5. 座標換算：舞台有 CSS transform 縮放，算滑鼠在元素裡的位置時，用 getBoundingClientRect() 的實際寬高比例換算回 px（api.canvas 已經處理好）
6. 動畫用 requestAnimationFrame，用時間差算位置；stop() 之後不能有任何計時器或動畫還在跑
7. 程式碼加中文註解；數值（關卡資料、容錯、星星門檻、顏色）集中成檔案開頭的具名常數 SCENE_CONFIG
8. 介面文字一律繁體中文、台灣用語

【回覆最後的自檢表 — 逐條寫「有／沒有」並說明】
- 是否完全照骨架、只寫場景？mount 欄位是否照本關設定一字不改？
- 每關的 api.finish 都有給 image（canvas 或 dataURL）嗎？星星規則跟本關設定一樣嗎？
- stop() 是否清掉所有動畫、計時器與 document 監聽？重複 start 是否從乾淨狀態開始？
- 1366×657 是否一屏不捲動？工具與按鈕是否 ≥ 44px？按鈕字有沒有斷行？
- 是否用 pointer events，平板觸控能玩？
- 本關的「學習能力」在遊戲裡哪個操作練到？逐條說明
- 有沒有用 emoji 當圖示、<ruby>、外部圖片或其他函式庫？
```

## 本關設定

### unit24（調色魔法鍋）

```
【本關設定】資料夾 units/unit24-color-cauldron/
mount：unit: 24, title: '調色魔法鍋', grade: '1–2 年級', zhuyin: true, submit: true,
  howto: '把紅、黃、藍顏料拖進大鍋，煮出客人點的顏色！',
  teach: '三原色混色、深淺變化｜生活課程 2-I-1'
levels（4 關）：橘色南瓜、綠色青蛙、紫色葡萄、淺藍天空

【玩法】
- 左邊：森林小動物客人＋對話框，台詞用 class="ai-zy"。台詞固定用這幾句（不要自己改字，字型會照字畫注音）：
  第 1 關「我要橘色的南瓜！」、第 2 關「我要綠色的青蛙！」、第 3 關「我要紫色的葡萄！」、第 4 關「我要淺藍色的天空！」
- 上方 5 瓶顏料：紅、黃、藍、白、黑（大、好拖，≥ 80px 寬）；中間一口有臉的大魔法鍋（跟開始畫面主角同一個鍋）
- 拖顏料瓶到鍋子上放開＝加 1 份；鍋裡顏色即時變成混出來的顏色、冒泡泡；旁邊小卡顯示「鍋裡加了：紅 1、黃 1」與「混出來是：橘色」
- 右邊一張這關物件的線稿（南瓜、青蛙、葡萄、天空雲朵）貼在白畫布上；按「倒到圖上」就把鍋裡的顏色填進線稿
  顏色對 → 客人跳舞、說謝謝、出現星星，然後呼叫 api.finish；顏色不對 → 客人照樣收下（「這個顏色也很特別」），稱讚句說出正確配方，呼叫 api.finish 給 1 顆星（寬鬆過關）
- 「倒掉重來」清空鍋子
- 三種原色都加進去 → 變成泥巴色，鍋裡跳出一隻泥巴怪做鬼臉，顯示 class="ai-zy" 的句子「哎呀，煮出泥巴色了！倒掉再試一次。」

【混色規則 — 一定要照美術課顏料（減色）的規則，用查表，不可以用 RGB 平均】
- 以「比例」判斷，不看總份數：紅:黃 = 1:1 跟 2:2 一樣是橘色
- 單色：紅 #E53935、黃 #FDD835、藍 #1E88E5、白 #FFFFFF、黑 #263238
- 兩原色等量：紅＋黃＝橘 #FB8C00、黃＋藍＝綠 #43A047、紅＋藍＝紫 #8E24AA
- 兩原色不等量：偏多的那邊（例 紅2＋黃1＝紅橘 #F4511E、黃2＋紅1＝黃橘 #FFB300），用查表或在兩色間內插，名稱寫「偏紅的橘色」這類
- 三原色都有＝泥巴色 #6D4C41（不論比例）
- 加白＝變淺（跟白色按比例混），加黑＝變深；例 藍＋白＝淺藍 #90CAF9
- 目標：第 1 關 橘（紅:黃 1:1）、第 2 關 綠（黃:藍 1:1）、第 3 關 紫（紅:藍 1:1）、第 4 關 淺藍（藍:白 1:1）

【星星】第一次倒到圖上就對 → 3 顆；倒錯 1–2 次後才對 → 2 顆；倒錯 3 次以上才對、或倒了不對的顏色 → 1 顆（倒錯也直接過關）
【finish 的 image】用 canvas 畫出「上好色的物件」（線稿＋填色），不是截整個畫面
【學習能力】三原色混色（紅黃藍兩兩混出橘綠紫）、加白變淺；用滑鼠拖曳放開
```

### unit25（線條小火車）

```
【本關設定】資料夾 units/unit25-line-train/
mount：unit: 25, title: '線條小火車', grade: '1–2 年級', zhuyin: true, submit: true,
  howto: '按住滑鼠，跟虛線畫一條鐵軌。',
  teach: '線條的種類與感覺、按住拖曳｜生活課程 4-I-1'
levels（4 關）：直直的線、彎彎的波浪線、尖尖的鋸齒線、自由軌道

【玩法】
- 大白畫布上有一條粗虛線（起點有月台、終點有小房子），孩子按住滑鼠沿虛線畫出鐵軌（用 api.canvas，筆刷粗 14px、深棕色）
  第 1 關直線、第 2 關波浪線、第 3 關鋸齒線；第 4 關「自由軌道」沒有虛線，孩子自己從月台畫到小房子
- 放開滑鼠後，小火車（有臉、冒煙）**沿著孩子自己畫的那條線**開過去（取 onStroke 的 path，依長度等速前進）；
  開過的地方沿線長出花、草、小樹；畫歪的地方火車會晃一下（好笑），但不會翻車、不判失敗
- 線沒畫到終點：火車開到線尾停下來按喇叭，提示「還沒到小房子喔」，可以接著再畫一筆（多筆串起來算同一條鐵軌）
- 右側面板：這種線的名字＋一句感覺（「波浪線：像海浪一樣溫柔」「鋸齒線：像閃電一樣有力」）＋「完成」按鈕（畫過一筆就能按；火車到站時按鈕跳一下提醒）
- 復原、清除按鈕

【容錯（一年級手還不穩，要寬）】
- 覆蓋率：把虛線取樣成點，鐵軌經過某點 28px 以內就算畫到；覆蓋率＝畫到的點／全部點
- 偏離虛線超過 28px 的地方火車放慢、晃一下，不扣分、不出現錯誤
【星星】覆蓋率 ≥ 75% → 3 顆；≥ 50% → 2 顆；其他（含沒畫到終點）→ 1 顆；第 4 關自由軌道從月台連到小房子 3 顆、沒連到 1 顆
【finish 的 image】畫布（鐵軌＋長出來的花草）畫成一張 canvas
【學習能力】認識直線、波浪線、鋸齒線並說出它們給人的感覺；滑鼠按住拖曳的精細動作
```

### unit26（對稱魔鏡工坊）

```
【本關設定】資料夾 units/unit26-mirror-workshop/
mount：unit: 26, title: '對稱魔鏡工坊', grade: '3–4 年級', zhuyin: false, submit: true,
  howto: '在左邊畫畫，魔鏡會同時畫出右邊，做出對稱的作品。',
  teach: '對稱造形、點線面創作｜藝術 視E-II-1、視E-II-3'
levels（4 關）：修好蝴蝶翅膀、設計面具、湖面倒影、萬花筒雪花

【玩法】
- 中間大白畫布（api.canvas）中央有一條藍色虛線「鏡子線」；用 setMirror 讓孩子畫的每一筆同時鏡射
- 左工具面板：筆刷 3 種粗細、12 色色盤（4×3）、橡皮擦、復原、清除
- 右側：對稱模式 4 格（左右對稱、上下對稱、萬花筒 4 份、雪花 6 份，用小圖示＋字），目前模式藍框＋✓；「完成」大按鈕
- 每關預設模式與底圖（底圖畫在畫布底層，淡淡的，孩子在上面畫）：
  第 1 關 修好蝴蝶翅膀：左右對稱，左半邊有一隻翅膀的淡色輪廓，任務條「修好蝴蝶的右邊翅膀」
  第 2 關 設計面具：左右對稱，淡淡的面具外框
  第 3 關 湖面倒影：上下對稱，上半是天空、下半是湖水的淡色背景，任務條「畫出山和樹，湖面會出現倒影」
  第 4 關 萬花筒雪花：預設雪花 6 份，可以自己切換 4 種模式自由創作
- 每一關都可以切換模式（第 1–3 關切換後任務條提醒「這關建議用 ○○ 對稱」，不阻止）
- mirror 函式：左右 p => [{x:W-p.x, y:p.y}]；上下 p => [{x:p.x, y:H-p.y}]；萬花筒 4 份＝左右＋上下＋對角；雪花 6 份＝以中心旋轉 60° 的 5 個點＋各自鏡射（共 12 個點，像真的雪花）

【星星】畫的筆數 ≥ 6 → 3 顆；≥ 3 → 2 顆；≥ 1 → 1 顆（這關重在創作，不評像不像）
【finish 的 image】畫布 canvas（含底圖與孩子的畫）
【學習能力】認識線對稱與旋轉對稱的造形；用點、線、面組合出對稱圖案（可以跟數學的線對稱連起來）
```

### unit27（小畫家任務局）

```
【本關設定】資料夾 units/unit27-paint-mission/
mount：unit: 27, title: '小畫家任務局', grade: '3–4 年級', zhuyin: false, submit: true,
  howto: '照著目標圖，用繪圖工具畫出一模一樣的圖，步數越少星星越多。',
  teach: '電腦繪圖工具、拆解步驟｜藝術 視E-II-2；資訊課小畫家'
levels（4 關）：紅綠燈、小房子、機器人、我的招牌

【玩法】
- 上方一條工具列（像真的繪圖軟體：圖示＋字，分組用直線隔開）：直線、矩形、橢圓、三角形｜填色桶、橡皮擦｜選取、複製、貼上｜復原；右邊色盤 8 色
- 左「目標圖」、右「我的畫布」（兩個白畫布並排）；右側或下方「步數計：已用 N 步｜標準桿 M 步」＋一句提示＋「完成」按鈕
- 圖形是物件（不是點陣）：每個圖形 { type, x, y, w, h, stroke, fill }
  直線／矩形／橢圓／三角形：在畫布上按住拖曳畫出；填色桶：點一個圖形內部，把它填成目前顏色
  選取：點一個圖形選起來（藍色虛線框＋四角控制點），可拖曳移動；複製＋貼上：貼上的副本出現在旁邊，選取中可直接拖去對的位置
  橡皮擦：點一個圖形刪掉；復原：回上一步（復原本身不算步數）
- 步數：畫一個圖形、填一次色、貼上一次、刪掉一次各算 1 步；選取與移動不算
- 每關目標圖（座標以畫布 520×400 為準）：
  第 1 關 紅綠燈：黑色直立矩形＋三個圓（紅黃綠），標準桿 7（1 矩形＋填色、1 圓＋填色、複製貼上 2 次、改填 2 次…自行算出合理最少步數）
  第 2 關 小房子：矩形屋身、三角屋頂、4 扇一樣的窗、門；標準桿 9（提示句「4 扇窗都一樣，有沒有更快的方法？」）
  第 3 關 機器人：頭、身體、手腳都是矩形，眼睛兩個圓；標準桿 12
  第 4 關 我的招牌：沒有目標圖，自由用工具設計一個班級招牌，至少用 3 種工具就算完成
- 「完成」時比對：目標每個圖形都要在我的畫布找到一個「同類型、位置相差 ≤ 30px、寬高相差 ≤ 30%、填色相同」的圖形
  沒全部對上也直接過關（寬鬆）：呼叫 api.finish 給 1 顆星，稱讚句說「還差 N 個圖形」

【星星】全部對上且步數 ≤ 標準桿 → 3 顆；≤ 標準桿 + 3 → 2 顆；其他（含沒全對上）→ 1 顆；第 4 關用了 3 種以上工具 → 3 顆、不到 3 種 → 2 顆
【finish 的 image】我的畫布畫成一張 canvas
【學習能力】使用電腦繪圖工具（圖形、填色、選取、複製貼上、復原）；把圖拆成步驟、找出重複的部分用複製貼上（運算思維）
```

```

- 工具：橡皮擦（變回白色）、復原、清除；1–2 年級的關說明句用 class="ai-zy"

【學習能力】低年級：照數字找顏色、對應；中年級：用座標找位置，認識數位圖片由像素組成
```
